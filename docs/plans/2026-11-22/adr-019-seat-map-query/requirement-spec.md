## 1. 목표·대상 (필수)

seat-reservation-lab `main-app`에 ① 헛선점 재현 스모크(캐시 없음) ② 좌석 맵 응답의 두 상태(`available` true / false) ③ 조회 후보 손잡이 `seat.seat-map.mode`(none · ttl · redis · event — 기본 none) ④ SSE 푸시 엔드포인트(손잡이 · 기본 끔) ⑤ 측정용 지표(화면 나이 · 캐시 적중)가 들어가고, ADR-019 설계 절이 채워지며, 새 ADR-020(조회 불일치의 결과 관리 — 가설)과 번호 이동(11차)이 문서에 반영된 상태. 기본 조회 방식은 바꾸지 않는다(측정 뒤 결정).

## 2. 경계·불변식 (필수)

- S1 두 상태: 좌석 맵 응답의 좌석마다 `status` 대신 `available`(bool)이 있다 — true = 지금 선점 가능하게 보이는 좌석 · false = HELD · RESERVED(만료 방식별 '보이는 상태' 판정은 지금 `SeatMapQuery` 그대로). 누구의 홀드인지 내지 않는다(ADR-014 그대로). 내부 `SeatStatus`(3값)와 선점 · 확정 경로는 바꾸지 않는다.
- S2 캐시 없음(none) = 지금 동작: 매 요청 SQL 한 문장 · 응답은 S1으로 바뀐 것 말고 같다(회차 없음 404 · 0석 회차 빈 목록).
- S3 화면 나이 상한: ttl · redis는 응답이 실제 상태보다 최대 TTL(+ 조회 시간)만큼 늦을 수 있다. 그 밖의 늦음은 없다(TTL이 지난 캐시를 내지 않는다).
- S4 이벤트 갱신 완전성: event 모드에서 **좌석 맵 상태를 바꾸는 모든 쓰기 경로**(AVAILABLE ↔ HELD — 1석 선점 · 묶음 선점 · 해제 · 만료 sweep · lazy 회수 · 대체 배정)가 **커밋 뒤** 그 회차 캐시를 무효화(또는 그 칸을 갱신)한다. 롤백된 쓰기는 화면을 바꾸지 않는다. HELD → RESERVED는 S1상 화면이 바뀌지 않는다.
- S5 시간 만료: lazy · lazy-sweep · derived 만료 방식은 쓰기 없이 시각만으로 홀드가 풀린다 — 이벤트로 잡을 수 없다. event 모드는 sweep 만료 방식에서만 허용하고, 다른 만료 방식과의 조합은 기동 검사로 거부한다(거부 메시지에 되돌릴 설정 안내 — ADR-018 '첫 거부에 안내' 계약과 같음). SSE도 같은 갱신 신호를 쓰므로 같은 조건.
- S6 장애 격리: redis 모드에서 Redis를 읽거나 쓰다 실패하면 DB 조회로 응답한다(조회 실패로 번지지 않음 · 지표에 실패 수). 다른 모드는 Redis에 연결하지 않는다(지금 health 설정 그대로).
- S7 SSE: `GET /api/schedules/{id}/seats/stream`은 연결 직후 전체 좌석 맵(S1) 한 번, 그 뒤 바뀐 좌석만 보낸다. 끊긴 클라이언트의 자원은 정리된다. 손잡이 끔(기본)이면 엔드포인트가 없다(404).
- S8 기존 경로 보존: 선점 · 해제 · 확정 · 보상 · 만료의 동작 · 응답 · 측정 계약은 그대로. 예외 = 좌석 맵 응답 상태값을 단언하는 기존 테스트(HELD · RESERVED → `available=false`)만 조정 — 목록을 log에 남긴다. 동작 단언은 그대로.
- S9 단일 앱 인스턴스: ttl · event 캐시는 앱 프로세스 안에만 있다(인스턴스가 여럿이면 인스턴스마다 다름 — 공유는 redis 후보의 몫). 다중 인스턴스 무효화는 범위 밖.
- 가로지르는 계약: 바꾸는 공유 값 = 좌석 맵 응답 상태값 · 새 손잡이 2개(`seat.seat-map.mode` · 푸시) → 함께 맞아야 하는 곳: 좌석 맵을 읽는 k6 스크립트(ADR-014 `lib14.js` · `s14-flow.js` 등 — 상태값을 보면 고친다) · 테스트 지원 코드(`Adr014ImplSupport` 등) · README API 설명 · yml 주석 · 기동 검사(S5)의 안내 · `application-test.yml`.
